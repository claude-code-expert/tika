## Interaction States

### State machine: `GeminiKeySection`

```
IDLE_NO_KEY   → user fills input → SAVING → (probe OK) IDLE_HAS_KEY
                                           → (probe fail) IDLE_NO_KEY + inline error

IDLE_HAS_KEY  → user clicks "키 교체" → REPLACE_MODE
              → user clicks "API 키 삭제" → DELETE_CONFIRM_OPEN

REPLACE_MODE  → user fills input → SAVING → (probe OK) IDLE_HAS_KEY
                                          → (probe fail) REPLACE_MODE + inline error
             → user clicks "취소" → IDLE_HAS_KEY

DELETE_CONFIRM_OPEN → user confirms → DELETING → IDLE_NO_KEY
                    → user cancels  → IDLE_HAS_KEY
```

### Input: API Key field

| State | Visual |
|-------|--------|
| Empty (default) | border: `#DFE1E6`, bg: `#fff` |
| Focused | border: `#629584`, box-shadow: `0 0 0 3px #E8F5F0` |
| Saving (disabled) | bg: `#F8F9FB`, cursor: `not-allowed`, opacity 0.7 |
| Error | border: `#DC2626`, box-shadow: `0 0 0 3px #FEF2F2` |
| Has value (masked, show mode off) | type="password" rendering |

### Button: "API 키 저장" (primary)

| State | Visual |
|-------|--------|
| Default | bg `#629584`, text white |
| Hover | bg `#527D6F` |
| Loading (probe in progress) | spinner + "확인 중..." label, disabled |
| Disabled (empty input) | opacity 0.45 |

### Button: "API 키 삭제" (destructive)

Rendered as `ghost` variant with danger text color `#DC2626`.  
On click: opens `ConfirmDialog` (existing component).

### Post-save toast (KEY-07 / D-07)

The existing `showToast` mechanism in `SettingsShell` must be **extended** for this phase to support a toast with an action button. Proposed approach: new `showToastWithAction` callback prop (or extend `ToastState` to include optional `action: { label: string; onClick: () => void }`).

Toast content after successful save:
- Type: `success`
- Message: "API 키가 저장되었습니다. 지금 복사하세요 — 창을 닫으면 전체 키를 다시 볼 수 없습니다."
- Action button label: "복사"
- Duration: 8000ms (extended from default 3000ms — user needs time to click copy)
- After close: no further copy opportunity

## RBAC Visibility Contract

| Role | Nav item visible | Section accessible | Direct URL `/settings?section=ai-key` |
|------|------------------|--------------------|---------------------------------------|
| OWNER | Yes | Yes | Renders GeminiKeySection |
| MEMBER | No | No | Redirected to `?section=general` |
| VIEWER | No | No | Redirected to `?section=general` |

Implementation: `SettingsShell` checks `role === 'OWNER'` before including `'ai-key'` in `visibleNavItems`. The existing `isViewer` guard must be extended to cover non-OWNER roles for this section. Fallback: if `rawSection === 'ai-key'` and role is not OWNER, force `initialSection = 'general'`.

## Accessibility Contract

| Element | Requirement |
|---------|-------------|
| API key input | `<label htmlFor="gemini-api-key">` connected via `id` |
| Show/hide toggle | `aria-label="API 키 표시"` / `aria-label="API 키 숨기기"` (toggle based on state) |
| Inline error | `role="alert"` on the error div — announced immediately on probe failure |
| Save button (loading) | `aria-busy="true"` when in SAVING state |
| Delete confirm dialog | Uses existing `ConfirmDialog` which already has `role="alertdialog"` + `aria-modal="true"` |
| Toast | `role="status"` + `aria-live="polite"` — matches existing toast pattern in SettingsShell |
| Nav item (AI 설정) | Standard `<button>` with text label — no aria-label needed (text is visible) |

Keyboard support:
- Tab order: input → show/hide toggle → save button → (cancel button in edit mode)
- ESC: closes ConfirmDialog (existing ConfirmDialog handles this)
- Enter in input: does NOT submit (prevent accidental save on paste)
